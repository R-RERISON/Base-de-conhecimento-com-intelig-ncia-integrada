# KB2Ops — Matriz de Herança Visual

## Objetivo

Tratar KB2Ops como patrimônio de experiência do produto, sem reproduzi-lo de forma acrítica. Cada padrão/tela relevante deve ser classificado por evidência visual real.

## Classificação

### PRESERVAR

Usar quando o padrão do KB2Ops:

- resolve bem a jornada;
- reduz esforço cognitivo;
- tem boa hierarquia visual;
- continua compatível com a arquitetura atual;
- não depende de writer, schema ou infraestrutura descontinuada.

### EVOLUIR

Usar quando a intenção é boa, mas o padrão precisa:

- ser alinhado ao Design System v1;
- melhorar acessibilidade/responsividade;
- reduzir densidade ou fragmentação;
- adaptar-se ao novo owner de Summary/Classificação;
- ser desacoplado de tecnologia antiga.

### DESCARTAR

Usar quando o padrão:

- reproduz arquitetura antiga sem valor atual;
- conflita com WordPress/Elementor como fonte editorial;
- cria writer paralelo;
- depende de infraestrutura que o projeto não quer manter;
- aumenta complexidade sem benefício operacional.

## Evidência necessária

Nenhum item deve ser classificado por memória ou descrição genérica. Para fechar UX-040 precisamos, sempre que disponível, de:

- screenshot/tela original;
- jornada representada;
- ação primária;
- informação exibida;
- limitações conhecidas;
- dependências técnicas relevantes.
