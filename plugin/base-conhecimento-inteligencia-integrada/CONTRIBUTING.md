# Contributing

## Regras

1. Preserve contratos e gates fechados.
2. Não altere o Lexical Ranker sem SPEC/gate explícito.
3. Não introduza segundo pipeline de Search.
4. Não faça escrita editorial em runners de diagnóstico.
5. Toda mudança funcional deve possuir teste/evidência proporcional.
6. PARTIAL/GAP/UNKNOWN_ENVIRONMENTAL no Master Functional Parity Ledger não pode ser tratado como concluído.
7. Não promova 1.0.0 antes do CUT-1490.

## Fluxo

- branch por SPEC/gate;
- mudanças pequenas e rastreáveis;
- validação local;
- evidência ambiental quando aplicável;
- PR DRAFT enquanto o gate não estiver fechado.
