## T525 — decisão WordPress-first

Selecionada: **C — Search Retrieval Projection post-level própria**.

Storage:
- uma tabela: `{$wpdb->prefix}bdc_kb_search_documents`;
- uma Option de estado: `bdc_kb_search_projection_state`, autoload=false.

Não criar:
- Golden table;
- FULLTEXT;
- item index;
- queue;
- analytics/query log;
- embeddings/vectors;
- storage ASI.

## Justificativa

WP_Query é preservado como fallback, porém não atende todo o contrato:
- 91/610 posts possuem gap semântico;
- 14/18 posts com Summary possuem sinal fora da busca nativa;
- Technical Challenges R-510 incluem Summary e Elementor/Content Extractor.

Uma Projection é a menor infraestrutura que resolve cobertura, ranking por campo, explicabilidade e rebuild sem reprocessar Elementor/HTML no read path.

FULLTEXT foi negado no v1 porque ainda não há benchmark que demonstre necessidade no corpus atual de 623 posts.

## Retrieval v1 autorizado para G-530

- SQL LIKE bounded;
- strict all-token;
- relaxed any-token para completar pool;
- ordem de candidatos `post_id ASC`;
- candidate cap 200;
- result default 20 / hard cap 50;
- revalidação WordPress antes do ranking;
- ranker PHP determinístico.

## Fallback

Projection não ready:
- usar WP_Query native relevance;
- response `degraded`;
- score=null;
- fallback nunca pode produzir Golden/G-550 PASS;
- nunca usar ASI.

## Segurança

- Search: `edit_posts`;
- cada resultado: `edit_post(post_id)`;
- rebuild/Golden: `manage_options` + POST + nonce;
- no query logging;
- no identity/IP/session/journey;
- Projection nunca concede acesso.

## Rollback/Rebuild

- rebuild explícito;
- nenhuma reindexação em page load;
- estado `building` força fallback;
- upsert idempotente;
- rows stale removidas somente após passagem completa;
- falha não toca conteúdo editorial;
- deactivation não remove tabela;
- uninstall não destrutivo por default.
